# devcontainer-features

Modern dev container features for deep learning and Python development. This
collection focuses on fast rebuilds, reproducible tool installs, and support
across the Linux images commonly used for development containers.

## Features

| Feature | What it does | Main options |
|---|---|---|
| [`package`](./src/package/README.md) | Installs system packages across apt, dnf/yum, apk, pacman, and zypper images. | `package`, `apt`, `dnf`, `apk`, `pacman`, `zypper` |
| [`uv`](./src/uv/README.md) | Installs `uv` and centralizes Python interpreter, project environment, and cache directories under a Docker volume. | `version`, `toolsToInstall` |
| [`huggingface`](./src/huggingface/README.md) | Installs the Hugging Face Hub CLI via `uv` and caches Hugging Face data under a Docker volume. | none |
| [`hf-mount`](./src/hf-mount/README.md) | Installs Hugging Face `hf-mount` and its NFS backend for mounting Hub Buckets and repos as local filesystems. | `version` |
| [`ollama`](./src/ollama/README.md) | Installs Ollama for local LLM serving and caches downloaded models under a Docker volume. | `version` |
| [`llama-cpp`](./src/llama-cpp/README.md) | Installs llama.cpp prebuilt binaries, including `llama-server`, for local LLM serving. | `version`, `backend` |
| [`miniforge`](./src/miniforge/README.md) | Installs Miniforge for the remote user, including `conda` and `mamba`, with optional shell initialization. | `version`, `initShell` |
| [`micromamba`](./src/micromamba/README.md) | Installs the standalone `micromamba` executable with optional shell initialization. | `version`, `initShell` |
| [`codex`](./src/codex/README.md) | Installs Codex CLI and synchronizes file-based ChatGPT credentials through a shared Docker volume. | `version` |

The `codex` feature uses the fixed `codex-auth` volume so trusted dev
containers on the same Docker host can share ChatGPT login state. API-key
credentials are not copied into or restored from that volume.

## Quick Start

Add a feature to `.devcontainer/devcontainer.json`:

```jsonc
{
  "image": "mcr.microsoft.com/devcontainers/base:ubuntu",
  "features": {
    "ghcr.io/stacit-ai/devcontainer-features/uv:1": {
      "version": "latest"
    },
    "ghcr.io/stacit-ai/devcontainer-features/miniforge:1": {
      "initShell": "auto"
    }
  }
}
```

Use `package` when another feature or devcontainer needs system dependencies:

```jsonc
{
  "features": {
    "ghcr.io/stacit-ai/devcontainer-features/package:1": {
      "package": "curl,ca-certificates",
      "apt": "build-essential",
      "dnf": "gcc,gcc-c++"
    }
  }
}
```

## Development

Each feature is maintained as a three-part slice:

```text
src/<feature>/              # devcontainer-feature.json and install.sh
spec/<feature>.md           # design notes, options, platforms, gotchas
test/<feature>/             # feature tests, scenarios, compatibility images
```

Common local commands:

```bash
just validate
just lint uv
just test-image uv mcr.microsoft.com/devcontainers/base:ubuntu
just test-scenarios uv
just test-duplicate uv
```

Feature tests use `devcontainer features test` and the standard
`dev-container-features-test-lib` assertions.

## Documentation

The root `README.md` is the human-maintained project overview. Keep it focused
on public user-facing information: available features, important options,
usage examples, and development workflow.

Feature-level `src/<feature>/README.md` files are generated by the release
workflow from `devcontainer-feature.json`; do not edit them manually. Use
`spec/<feature>.md` for implementation design, supported platforms, and
feature-specific gotchas.

When adding a feature, changing a feature interface, or changing user-visible
feature behavior, update this root README with the smallest change that
accurately reflects the new public information.
